# AI Usage Disclosure

## 1. Purpose

AI tools were used as development assistance while building the Logistics ETA Prediction and Delay Detection System. They helped with understanding technical concepts, planning the implementation, debugging errors, reviewing code logic, and preparing documentation.

## 2. Areas Where AI Assistance Was Used

| Area | How AI Assisted |
|---|---|
| Project planning | Helped break the challenge requirements into development stages and identify the required components. |
| Data generation | Assisted with designing Python and Pandas-based synthetic data generation for shipments, routes, tracking events, facilities, and disruptions. |
| Database design | Helped understand relational tables, primary keys, foreign keys, and database relationships. |
| Feature engineering | Assisted with designing time-based ETA snapshots and separating model features from ground-truth labels. |
| Data validation | Helped identify validation rules for duplicate records, missing relationships, route sequences, and shipment lifecycle consistency. |
| Negative scenarios | Assisted with designing tests for late-arriving events, future-event leakage, disconnected routes, and inconsistent delivery statuses. |
| Debugging | Helped investigate Python errors, incorrect indentation, missing variables, and integration issues. |
| Documentation | Assisted with preparing project explanations, setup instructions, assumptions, and validation documentation. |

## 3. Representative AI Assistance Requests

The following are representative examples of the types of prompts used during development:

- Help design a reproducible synthetic logistics dataset using Python and Pandas.
- Explain how to model shipments, shipment legs, tracking events, facilities, and routes in PostgreSQL.
- Help implement ETA prediction features using only information available at a prediction timestamp.
- Explain how to prevent data leakage in time-based machine learning datasets.
- Help validate route sequences and shipment lifecycle transitions.
- Help write pytest cases for late-arriving events and other negative scenarios.
- Explain errors encountered while integrating project modules.

These examples describe the categories of assistance used; they are not presented as a verbatim transcript of every prompt.

## 4. Human Review and Responsibility

AI-generated suggestions were reviewed and integrated during development. The project code was executed, tested, and modified to address implementation errors.

The developer is responsible for understanding the implementation, verifying outputs, reviewing generated data, and explaining the design decisions and limitations.

AI assistance does not replace testing or technical understanding.

## 5. Data and Reproducibility

The project uses synthetic data generated by the project's Python pipeline. The random seed is `20261022`.

A source manifest records dataset names, record counts, columns, generation methods, and SHA-256 checksums.

A validation summary records dataset integrity checks, feature and label validation, and automated test results.

## 6. Limitations

The system is a prototype developed using synthetic logistics data. Its results should not be interpreted as validated real-world carrier performance or production ETA accuracy.

The generated data, assumptions, model outputs, and validation results require further evaluation using real operational logistics data before production use.
